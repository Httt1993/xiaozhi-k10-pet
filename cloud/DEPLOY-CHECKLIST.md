# 腾讯云 SCF 部署清单（照着点，3 分钟）

> 目标：把 `cloud/dist/pet-cloud-scf.zip` 变成一个能访问的网址。  
> 全程不用买服务器、不用备案域名、不用绑卡付费（走免费额度）。  
> 唯一前提：有一个腾讯云账号（微信扫码就能注册）。

---

## 第 0 步：先在本机确认 zip 是最新的

```bash
cd k10-pet-build/cloud
node build.mjs --check
```

- 看到 **`✓ 本机 zip 是最新的，可以直接上传`** → 直接进第 1 步。
- 看到 **`✗ 源码已改动，zip 过期：xxx.js`** → 先跑 `node build.mjs` 重打包（40 项自检全过才出包），再回来 `--check` 一遍。
- 看到 **`✗ zip 内容与打包记录不一致`** → 这个包被替换或拷坏了，一定重打包，别硬传。

> 为什么不用「看修改时间」：改完又改回来、从别处拷一份旧 zip 覆盖、系统时钟跳一下，  
> 文件时间都可能是"新"的。`--check` 算的是文件内容 sha256，改没改它说了算。

---

## 第 1 步：进控制台，新建函数

打开 **<https://console.cloud.tencent.com/scf>**

### 1.0 先过「服务授权」（首次使用必弹一次）

如果你看到这个框：

> 当前账号 xxx 尚未授权腾讯云函数服务操作 COS/CMQ/CLS/APIGW 等云资源权限…

**这不是要你填授权码，也没有任何验证码或密码。** 它是让云函数有一个"服务角色"，  
能替你读写 COS（存代码包）、CLS（写日志）、API 网关（提供函数 URL）。不授权就建不了函数。

1. 点 **「前往访问管理」**（右边那个蓝按钮，不是「取消」）
2. 跳到 CAM 角色授权页，页面会显示角色名 **`SCF_QcsRole`**、策略 `QcloudAccessForScfRole`
3. 点 **「同意授权」** —— 系统自动创建角色，你会被弹回控制台
4. 刷新页面，重新点「新建」，这次能正常往下走

三个说明：

- **这一步不花钱、不绑卡**，它只是权限，不是购买。
- 如果你登录的是**子账号/协作者**，这个授权必须由**主账号**来做，你自己点不动。
- 后续如果又弹「开通日志服务 CLS」，同意即可（有新用户免费资源包）；  
  不想付日志钱可以之后在函数配置里关掉「日志投递」，详见 `README.md` 的「成本」一节。

### 1.1 填表

1. 左上角 **地域** 选 `广州`（选哪个都行，记住它，URL 里会出现 `ap-guangzhou`）
2. 点左侧 **函数服务** → **新建**
3. 选 **从头开始**
4. 按下面这张表填，没提到的都保持默认：

| 输入框   | 填什么                               | 说明             |
| ----- | --------------------------------- | -------------- |
| 函数类型  | **事件函数**                          | 别选 Web 函数      |
| 函数名称  | `pet-cloud`                       | 随便起，别用中文       |
| 运行环境  | **Nodejs18.15**（或 Nodejs20）       | 不要选 16 及以下     |
| 提交方法  | **本地上传 zip 包**                    | 千万别选「在线编辑器」    |
| 函数代码  | 上传 `cloud/dist/pet-cloud-scf.zip` |                |
| 内存    | **128 MB**                        | 够用，越小越省额度      |
| 执行超时  | **10 秒**                          | 默认 3 秒太短，冷启动会超 |
| 初始化超时 | 60 秒（默认）                          |                |

1. 往下滚到 **高级配置 → 环境变量**，加两条：

| 变量名        | 值                        | 必填                                      |
| ---------- | ------------------------ | --------------------------------------- |
| `PET_KEY`  | 自己定一个口令，例如 `qiaoli-2026` | **建议填**。填了之后设备和看板都要带这个口令，别人拿到地址也改不了你的宠物 |
| `PET_NAME` | `乔利`                     | 可选，宠物名字                                 |

1. 点 **完成 / 创建**

> 如果页面提示「是否立即创建触发器」，跳过，下一步单独配。

## 第 2 步：开函数 URL（这就是你要的「家长后端网址」）

1. 进函数详情页 → 左侧 **函数管理** → **函数 URL**
2. 点 **启用 / 新增**
3. **鉴权类型选「无需鉴权」** ← 关键，选错了设备访问会被腾讯云拦成 401
4. 保存，页面会给出一个地址，长这样：

```
https://pet-cloud-1234567890.ap-guangzhou.tencentscf.com/
```

**把这个地址复制下来。**

---

## 第 3 步：验活（浏览器直接打开）

打开刚复制的地址，应该看到一个中文页面，标题「小智宠物云端引擎 · 运行中 v1.1.0」，  
上面有个橙色的 **「打开家长看板 →」** 按钮。

- 看到页面 → 成功，进第 4 步
- 看到 404 → 地址末尾补一个 `/` 再试
- 看到 401 / 鉴权失败 → 第 2 步的鉴权类型选错了，改回「无需鉴权」
- 什么都打不开 → 地域选错或函数没部署成功，截图发我

再点「打开家长看板 →」，会让你输口令（就是第 1 步设的 `PET_KEY`），输完能看到宠物状态卡片  
（这时候还没设备上报，会显示「还没有收到设备上报」，这是正常的）。

## 以后改了云端代码：怎么重新部署（不用重建函数）

函数建好之后再改 `cloud/scf/*.js`，只需要换代码，别的都不用动：

1. 本机打新包并自检

   ```bash
   cd k10-pet-build/cloud
   node build.mjs          # 48 项自检全过才出包
   node build.mjs --check  # 确认 zip 和源码一致
   ```

2. 控制台进 **函数管理 → 函数代码**，右上角 **本地上传 zip 包** → 选 `cloud/dist/pet-cloud-scf.zip` → 点 **部署**
3. 等状态回到「正常」（十几秒），刷新函数 URL，自检页标题后面的版本号会变

环境变量（`PET_KEY` / `PET_NAME`）不会因为换代码而丢，不用重填。
**固件也不用重烧** —— 只要 `PET_CLOUD_URL` 和口令没变，设备那边什么都不用做。

## 常见坑（按踩过的概率排序）

| 现象                                    | 原因                         | 解法                                                     |
| ------------------------------------- | -------------------------- | ------------------------------------------------------ |
| 创建函数失败：`EntryFile did not find in code or layers` | 运行环境不是 Node，或执行方法写错，或 zip 没真正上传 | 见下面单独一节 |
| 浏览器打开 401 / `{"code":"Unauthorized"}` | 函数 URL 鉴权类型选了「鉴权」          | 改成「无需鉴权」                                               |
| 部署成功但打开 502                           | 入口写错                       | 函数配置 → 执行入口填 `index.main_handler`                      |
| 日志报 `MODULE_NOT_FOUND`                | 上传的是文件夹不是 zip，或 zip 里有中文目录 | 一定上传 `cloud/dist/pet-cloud-scf.zip` 这个文件本身             |
| 设备日志 `HTTP 404`                       | 填的是控制台页面网址，不是函数 URL        | 只复制第 2 步那个 `*.tencentscf.com` 的地址                      |
| 设备日志 `HTTP 401`                       | 固件里的口令和云函数 `PET_KEY` 不一致   | 两边改成一样（我帮你改固件）                                         |
| 免费额度会不会被心跳吃光                          | 不会                         | 见 README「成本」一节：前三个月免费，之后约 0.1 元/月 |

### `EntryFile did not find in code or layers` 怎么排

这个报错的意思是：云函数解压完代码包，**没找到入口文件**。按顺序查这三处，前两处占九成：

1. **运行环境必须是 Nodejs**。如果选了 Python / PHP / Java / Go，它会去找 `index.py` 之类，
   当然找不到 `index.js`。改成 `Nodejs18.15`（或 `Nodejs20`）。
2. **执行方法（入口）必须是 `index.main_handler`** —— 全小写 `index` + 点 + 下划线 `main_handler`。
   写成 `index.mainHandler`、`index.handler`、`main_handler` 都会报这个错。
3. **确认 zip 真的传上去了**。「本地上传 zip 包」选完文件后，输入框旁边应该显示
   `pet-cloud-scf.zip`（26 KB 左右）。如果显示「未选择文件」，说明没选中，代码是空的。

我们这边已确认包本身没问题（5 个文件都在根目录、能被标准解压器读出、CRC 全对）。
另外 2026-10-26 已经把 zip 的压缩方式从未压缩（store）改成 deflate，体积 64 KB → 26 KB，
排除"云上构建器不认未压缩条目"这个少见原因。重新下一次包再试。
