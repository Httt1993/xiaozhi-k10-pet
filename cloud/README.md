# 云端宠物逻辑 · 集成说明

小智 K10 宠物养成的**状态演化服务**，跟固件放在同一个仓库里（`k10-pet-build/cloud/`）。
一台设备、一个云函数，不需要域名备案、不需要数据库、不需要常开电脑。

---

## 一分钟看懂在跑什么

```
孩子说「喂它吃个苹果」
        │
        ▼
小智云端大模型（听写 → 理解 → 决定调 self.pet.action）
        │  MCP over WebSocket（设备主动拨出，所以不需要公网 IP）
        ▼
设备固件  PetTools ──► PetCloud ──► HTTPS POST
        ▲                              │
        │                              ▼
        │                    腾讯云 SCF · pet-cloud-scf
        │                     pet-core.js 纯函数：
        │                       按时间差补算衰减
        │                       判生病 / 算金币 / 查任务
        │                              │
        └──── { status, say, events, state, server_ts } ◄──┘
                    │
                    ▼
          state 存 NVS  →  灯色 + 表情 + 语音回答
```

**一句话分工：云端负责「算」，设备负责「记」和「表现」。**

---

## 为什么云函数是无状态的（这是刻意的，不是偷懒）

养宠物的核心是「时间过去了多久」，不是「谁记得状态」。

```
设备把 state（含 lastDecay 时间戳）整份传上去
        ↓
云端算：now - lastDecay = 几步衰减 → 逐步骤推 → 判是否饿到生病
        ↓
把新 state 整份回传，设备存进 NVS
```

带来的好处：

| 场景 | 结果 |
|---|---|
| 关机三天再开机 | 开机把 `lastDecay` 传上去，云端照样算出「饿了三天」，不用定时器 |
| 云函数冷启动 / 扩容 / 重新部署 | 不丢任何进度，因为状态根本不在云端 |
| 设备断网 | 固件用同一套规则本地演化，恢复后上传，云端 `normalizeDoc` 兼容 |
| 月度成本 | 一次调用约 **0.06 GB·s**（128 MB × 0.5 s），一万次/月约 600 GB·s（详见"成本"一节） |

如果改成「云端常驻 + 数据库」，要么烧掉四成免费额度（拨号器方案），要么得付数据库钱。
对一台放在家里的玩具来说不值得。

## 云函数接口

一个端点，全部用 POST JSON。地址是 SCF 的**函数 URL**。

```
POST https://<你的函数地址>/
Header: Content-Type: application/json
Header: X-Pet-Key: <口令，配了 PET_KEY 才需要>
```

### 请求体

```json
{
  "action": "feed",
  "state":  { ...上一轮云端回传的 state，首次传 null... },
  "args":   { "food": "苹果" },
  "ts":     1793017348
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `action` | 是 | 见下表 |
| `state` | 是 | 上轮返回的 `state` 原样带回；`null` 表示第一次，云端自动初始化 |
| `args` | 否 | 动作参数 |
| `ts` | 否 | 设备当前 Unix 时间戳。**与服务器相差超过 5 分钟会被忽略**，改用服务器时间 |

### 响应体

```json
{
  "ok": true,
  "code": "FED",
  "say": "苹果甜甜的，脆脆的，我还要！（饱食 +20，心情 +8）",
  "action": "feed",
  "status": { "hunger": 80, "energy": 82, "mood": 88, "sick": false,
              "coins": 18, "exp": 2, "level": 1, "fun_left": {...} },
  "events": [],
  "mood_word": "感觉还不错～",
  "state":  { ...新的完整状态，设备原样存 NVS... },
  "server_ts": 1793017348,
  "skew_sec": 0
}
```

| 字段 | 用途 |
|---|---|
| `ok` / `code` | 动作成功与否。失败码：`FULL` 吃饱了、`NO_COIN` 币不够、`NOT_SICK` 没生病、`WRONG_MED` 吃错药、`DAILY_CAP` 今日次数用完、`TOO_FAST` 连击被拦、`DUPLICATE` 重复报备 |
| `say` | **宠物自己的话**，模型直接转述给孩子 |
| `events` | 供固件做灯/脸联动的状态事件，按严重程度排序，取第一个使用 |
| `state` | 权威状态，设备原样存 NVS，下次带回来 |
| `skew_sec` | 服务器时间 − 设备时间。绝对值 > 300 时云端改用服务器时间算衰减 |

### 动作一览

| action | args | 做什么 |
|---|---|---|
| `sync` | — | 只补算衰减，不改其它。查状态前调它 |
| `feed` | `food` | 喂食。食物：小饼干 / 苹果 / 牛奶 / 胡萝卜 / 热汤面 / 小蛋糕 |
| `medicine` | `medicine` | 喂药。退烧药 / 感冒冲剂（治病）· 维生素（只保健） |
| `play` | — | 陪玩。花 3 币，心情 +18，精力 −8 |
| `heal` | — | 看病。花 10 币，一次治好 |
| `sleep` | — | 睡觉。精力 +20，饱食 −5 |
| `story` | `topic` | 讲故事。免费，每天 3 次 |
| `song` | — | 唱歌。免费，每天 3 次 |
| `teach` | `what` | 学东西。免费，每天 3 次 |
| `pet` | — | 摸头。免费不限次，心情只 +4（是陪伴，不是刷数值） |
| `chat` | `text` | 闲聊，不改数值 |
| `task_list` | `include_done` | 任务清单 |
| `task_submit` | `title` | 孩子报备完成 |
| `task_publish` | `title` `reward` | 家长布置任务 |
| `task_approve` | `title` 或 `task_id` | 家长确认发币（幂等，重复点不会重复发） |
| `task_reject` | `title` 或 `task_id` | 家长退回 |
| `coins` | — | 查金币 |
| `reset` | — | 重新养一只 |
| `ping` | — | 自检，返回配置和物品库 |

### 数值规则（`pet-core.js` 顶部 `DEFAULTS`，可用环境变量覆盖）

| 项目 | 默认 | 说明 |
|---|---|---|
| 衰减步长 | 0.5 小时 / 步 | 每步 饱食 −2、精力 −1、心情 −1（饿到 ≤10 时心情 −4） |
| 单次封顶 | 48 步（24 小时） | 防止久不开机被一次清零 |
| 生病条件 | 饱食为 0 持续 12 小时 | 生病期间心情每步额外 −3 |
| 等级 | 50 经验 / 级 | 每次动作 +2，治病 +6 |
| 新手金币 | 20 | 第一次初始化赠送 |
| 免费互动 | 每项每天 3 次 | 讲故事 / 唱歌 / 学东西各自计数 |
| 动作间隔 | 2 秒 | 挡住语音误识别连击刷币 |
| 任务确认 | 需要家长确认 | 让孩子知道「做完还要被检查」 |

## 部署（腾讯云 SCF，约 5 分钟）

### 第 1 步：打包

```bash
cd k10-pet-build/cloud
node build.mjs
```

脚本会先跑 27 项自检（模块可加载、冒烟调用、鉴权、坏 JSON 兜底、zip 路径用正斜杠…），
**任何一项不过就不产出 zip**。看到 `自检全部通过` 就拿到了
`dist/pet-cloud-scf.zip`（38.5 KB，零第三方依赖）。

### 第 2 步：新建云函数

打开 <https://console.cloud.tencent.com/scf> → **函数服务** → **新建**

| 项目 | 填什么 |
|---|---|
| 创建方式 | 从头开始 |
| 函数类型 | 事件函数 |
| 函数名称 | `pet-cloud-scf` |
| 地域 | 离你近的（广州 / 上海 / 北京） |
| 运行环境 | **Node.js 18** |
| 提交方法 | **本地上传 zip 包** → `cloud/dist/pet-cloud-scf.zip` |

> 不用勾「在线安装依赖」，包里没有任何第三方包。

### 第 3 步：改两个配置（漏一个就跑不起来）

函数详情 → **函数配置** → 编辑：

| 配置项 | 值 | 为什么 |
|---|---|---|
| **执行超时时间** | **10 秒** | 默认 3 秒够用，但冷启动偶尔要 4 秒 |
| 内存 | **128 MB** | 实际只用到 40 MB 左右 |
| 函数入口 | `index.main_handler` | 默认就是，确认一下 |

### 第 4 步：环境变量（可选但建议配口令）

同一页往下，**环境变量**：

| 变量名 | 值 | 必填 |
|---|---|---|
| `PET_KEY` | 自己编一个口令，如 `qiaoli-2026` | 建议。配了之后设备必须带同一个口令 |
| `PET_NAME` | 宠物名字，默认 `乔利` | 可选 |
| `PET_INIT_COINS` | 新手金币，默认 20 | 可选 |
| `PET_DECAY_STEP_HOURS` | 衰减步长（小时），默认 0.5 | 可选。调大 = 饿得慢 |

> 剩下所有数值都能用同名环境变量覆盖，见 `scf/pet-core.js` 里的 `DEFAULTS`。

### 第 5 步：拿到访问地址

函数详情页有两种入口，**有哪个用哪个**：

| 控制台入口 | 地址长什么样 |
|---|---|
| **函数 URL**（推荐，最简单） | `https://xxxxx.ap-guangzhou.tentcentcs.com/` |
| 触发管理 → 创建触发器 → **HTTP 触发**（API 网关） | `https://service-xxxx.gz.apigw.tencentcs.com/release/` |

两者都是腾讯云提供的默认域名，**不需要备案、不需要买域名**。

> 定时触发**不是必需的**。云函数无状态，定时触发只做心跳自检。
> 如果你想在控制台看到「函数还活着」的痕迹，可以加一个 `0 */30 * * * * *`（每 30 分钟）。

### 第 6 步：验证活了

**用浏览器直接打开那个地址**，应该看到一个中文自检页，写着「运行中 · v1.2.0」。
（版本号是你判断「代码到底更新没有」的唯一可靠依据 —— 换代码重新部署后这个数字会变。）

也可以用命令：

```bash
curl -X POST 'https://你的函数地址/' \
  -H 'Content-Type: application/json' \
  -H 'X-Pet-Key: 你的口令' \
  -d '{"action":"sync","state":null}'
```

第一次 `state: null` 会自动初始化一只新宠物，返回 `hunger:60, energy:80, coins:20`。

## 固件配置

打开 `main/boards/dfrobot/df-k10/pet_config.h`，填两行：

```c
#define PET_CLOUD_URL "https://xxxxx.ap-guangzhou.tentcentcs.com/"
#define PET_CLOUD_KEY "qiaoli-2026"
```

其它三个开关：

| 宏 | 默认 | 说明 |
|---|---|---|
| `PET_CLOUD_TLS_INSECURE` | 0 | 证书校验。**只有**连不上且确认是自签证书时才改 1 |
| `PET_CLOUD_AUTO_REACT` | 1 | 状态变化自动换灯色和表情。改成 0 则完全交给 AI 决定 |
| `PET_ENABLE_SENSORS` | 1 | 三个传感器。不动它 |

留空 `PET_CLOUD_URL` 就是**本地模式**：同一套数值规则在设备上跑精简实现，
不联网也能养，只是任务功能用不了。

> URL 也可以写进 NVS 覆盖编译期宏（命名空间 `pet_cloud`，键 `url` / `key`），
> 这样以后换地址不用重新烧固件。目前的固件没有暴露设置入口，改代码更快。

改完照常构建烧录即可，和以前的流程一样。

## 前后端怎么衔接

### 一次「喂苹果」的完整时序

| # | 谁 | 做什么 |
|---|---|---|
| 1 | 孩子 | 说「喂它吃个苹果」 |
| 2 | 小智云端 | 听写 + 理解，决定调 `self.pet.action` |
| 3 | 设备 | `PetTools` 收到工具调用，组 `{action:"feed", args:{food:"苹果"}}` |
| 4 | 设备 | `PetCloud::Act()` 把内存里的 state 一起打包 POST 给 SCF |
| 5 | SCF | `applyDecay()` 先补算到此刻 → 检查饱食度/金币 → 扣币加值 → 返回新 state + 话术 |
| 6 | 设备 | `ApplyResponse()`：新 state 覆盖内存 → `PersistState()` 写 NVS |
| 7 | 设备 | `ReactToEvents()`：如果事件变了，顺手改灯色和表情 |
| 8 | 设备 | 把 `say` 返回给模型，模型用自己的口吻说给孩子听 |

### 三处必须对齐的地方

改任何一处都要同步改另一处，否则离线/在线切换会出问题：

| 地方 | 云端 | 固件 |
|---|---|---|
| 数值规则 | `scf/pet-core.js` 的 `DEFAULTS` | `pet_cloud.cc` 顶部 `kDecayStepSec` 等常量 |
| 状态结构 | `initDoc()` / `normalizeDoc()` | `ActLocal()` 的初始化分支 |
| 话术 | `FOODS[].line` / `MEDS[].line` | `kFoods[].line` / `kMeds[].line` |

固件侧 `normalizeDoc` 等价物是"缺字段就补默认值"，所以云端加新字段不会让老固件崩。

### 失败时的行为

| 情况 | 发生什么 | 用户感知 |
|---|---|---|
| 没配 URL | 全程本地模式 | 正常玩，任务功能提示「要联网」 |
| 配了 URL 但连不上 | 降级本地演化，状态照存 NVS | 照常玩，日志里有 `降级本地` |
| 云端 5xx / 返回坏 JSON | 同上 | 同上 |
| 设备时钟偏差 > 5 分钟 | 云端改用服务器时间算衰减 | 无感，日志里有 `时钟相差 N 秒` |
| NVS 满写不进去 | 只打 warning，内存态继续跑 | 无感，只是重启会丢一部分进度 |
| 说话说得太快（2 秒内连击） | 云端返回 `TOO_FAST` | 宠物说「慢一点点啦，我还没反应过来～」 |

**任何情况下都不会因为云端挂了导致设备不能玩。**

### 指令是怎么送到设备的

看板点下去**不会立刻改状态**，而是进一个队列（`scf/store.js` 的 `pending`），
等设备下一次请求云函数时，由 `index.js` 的 `drainPending()` 压进设备刚上报的 `state` 上一起执行。

这么设计的原因：真状态在设备 NVS 里，云函数本身无状态。如果看板直接改云上的副本，
就会出现「云上一本账、设备一本账」，过两天必然对不上。宁可慢一步，不要两本账。

**送达时机**：两种情况——① 设备每 5 分钟一次的心跳（`PET_HEARTBEAT_SEC=300`，且只在待命/聆听时发）；
② 孩子跟小智说任何跟宠物有关的话（问饿不饿、喂饭、问任务…），设备立刻请求云函数，队列随之清空。
开机 30 秒后还会先同步一次，所以刚开机就点的指令不用等满 5 分钟。

### 为什么指令要「重发 + 回执」

云函数会同时活着好几个实例，而队列只存在**某一个实例的内存**里。
2026-10-26 实测：设备心跳落到另一个实例上，看板的 `pending` 从 1 变 0，但宠物数值一个都没变
—— 指令是跟着实例一起消失的，不是被设备取走了。两次实测丢两次。

不引入任何新服务的解法，是让**设备自己当回执**：

```
看板点一下 → 指令带一个毫秒时间戳 at 进队列（同时也记在手机 localStorage）
设备上报 → drainPending 把 at > state.pet.cmdAck 的取出来执行
         → 执行完把 at 写进 state.pet.cmdAck
设备把这份 state 存进 NVS，下次上报原样带回来
看板看到 ack >= at → 判定「已送达」，从本机队列删掉
看板 30 秒没等到回执 → 用同一个 at 再发一次（最多 8 分钟）
         → 落到哪个实例都能排上，落到同一个实例按 at 去重
         → 即使两个实例都送到设备，at <= cmdAck 会被跳过，不会重复喂饭
```

关键点：**`cmdAck` 存在设备的 NVS 里**，不是存在云上。
所以「重发」这件事无论发多少次、落到多少实例、跨多少次冷启动，都不会重复生效。

### 云上那份快照存哪

| 环境变量 | 后端 | 行为 |
|---|---|---|
| 设了 `PET_STORE_FILE` | `file` | 写文件。本地 `serve-local.mjs` 自动设成 `cloud/.pet-store.local.json`，重启不丢 |
| 没设（云上默认） | `mem` | 存模块级变量。SCF 热实例复用期间有效，实例回收/切换后看板会短暂变空，设备下次上报自动恢复 |

对「孩子今天吃了几顿饭」这个量级，`mem` 够用，所以默认不折腾数据库。
真要长期留存历史，正解是挂 COS 或数据库 —— 现阶段不值得为它加一个依赖。

**`mem` 的真实边界（2026-10-26 实测）**：
- 实例回收后快照消失 → 看板短暂显示「这一会儿还没有设备上报的数据」，设备下次心跳（≤5 分钟）就回来。
- 排队中的指令也会跟着实例消失 → 靠上面的「重发 + 回执」兜住，不会真的丢。
- 设备的真实状态一直在设备 NVS 里，**这一层丢的只是「看板显示」，不是宠物进度**。

## 常见问题

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 浏览器打开函数地址是 404 而不是自检页 | 用了 API 网关但路径不对 | URL 末尾要带 `/release/` 或 `/`，照控制台给的完整地址填 |
| 设备日志一直 `降级本地` | URL 填错 / 证书问题 / 设备连不上外网 | 先看日志里的具体错误：`连接失败: ESP_ERR_HTTP_CONNECT` = 网络或证书；`HTTP 401` = 口令不对 |
| `HTTP 404` | 填的是函数详情页网址，不是函数 URL | 回控制台复制「函数 URL」 |
| `HTTP 401` | `PET_CLOUD_KEY` 和云函数 `PET_KEY` 不一致 | 两边改成一样，或把云端 `PET_KEY` 删掉 |
| 一次动作要等 3 秒以上 | 首次 TLS 握手（约 1-2 秒）+ SCF 冷启动 | 正常。连续使用会快很多 |
| 设备堆内存报警 / 重启 | TLS 握手峰值内存不够 | 把 `PET_CLOUD_AUTO_REACT` 之类先关掉排除；仍不行则告知我，改成分批同步 |
| 宠物一直不饿 | 设备时间和真实时间差太多 | 看日志 `时钟相差 N 秒`；设备联网后 OTA 会校时，一般不用管 |

### 自己在电脑上验一遍（不上云）

```bash
cd k10-pet-build/cloud
node test-local.mjs      # 71 项断言：衰减/生病/金币/任务/节流/时钟保护/状态体积
node build.mjs           # 40 项自检 + 出 zip，同时写入指纹 dist/scf.stamp.json
node build.mjs --check   # 只读校验：本机 zip 是不是最新的，一秒出结果
node serve-local.mjs     # 起本地服务 → http://127.0.0.1:8901/?page=parent
```

**上传前先跑 `--check`。** 它按内容算 sha256 比对 `dist/scf.stamp.json`，
不看修改时间——改完又改回来、从 git 拉一份旧文件覆盖、系统时钟跳一下，
mtime 都会骗你，哈希不会。返回三种结果：

| 输出 | 含义 | 退出码 |
|---|---|---|
| `✓ 本机 zip 是最新的` | 可以上传 | 0 |
| `✗ 源码已改动，zip 过期：parent.js` | 列出哪个文件变了，重跑 `node build.mjs` | 1 |
| `✗ zip 内容与打包记录不一致` | 包被替换或损坏（比如从别处拷来的旧包） | 1 |

加 `--json` 输出机器可读结果，方便以后接进脚本：

```bash
node build.mjs --check --json
```

饿到生病 → 吃错药 → 对症吃药 → 玩耍 → 语音连击被拦 → 讲故事刷到上限 →
家长发任务 → 孩子报备 → 家长确认发币 → 设备时钟错乱保护。

## 成本（含 5 分钟心跳）

**先纠正一个容易搞错的前置条件：腾讯云中国站的免费额度只给前三个月。**

2024-01-01 起中国站规则（[免费试用额度](https://cloud.tencent.com/document/product/583/12282)）：

| 阶段 | 每月免费额度 |
|---|---|
| 开通当月起的**前三个月** | 调用 100 万次 + 资源 **100 万 GB·s** + 外网出流量 2 GB |
| **三个月后** | 免费试用额度归零，直接转按量计费（中国站没有"基础套餐费"这一项） |

> 国际站（tencentcloud.com）三个月后还保留"基础套餐"，每天扣 0.06 美元 ≈ 13 元/月。
> 中国站 2024 年已经取消这条，**不要被国际站文档吓到**。要验证就看你自己的账单页。

按量计费单价（[云函数基本能力产品定价](https://cloud.tencent.com/document/product/266/12281)，2025-03）：

| 计费项 | 单价 |
|---|---|
| 资源使用量 | 0.00011108 元/GB·s |
| 调用次数 | 0.0133 元/万次 |
| 外网出流量（中国大陆） | 0.80 元/GB |

先对齐一个容易搞错的单位：一次调用的资源用量 = 内存规格(GB) × 执行时长(秒)。
本函数 128 MB = 0.125 GB，纯 JS 计算实测 1 ms 级，算上冷启动加载模块，按 **0.5 秒** 估：

```
0.125 GB × 0.5 s = 0.0625 GB·s / 次
```

| 项目 | 用量 | 前三个月 | 三个月后折算 |
|---|---|---|---|
| 心跳 | 5 分钟一次 → 288 次/天 → **8,640 次/月** | 占 100 万次免费额度的 0.86% | 0.011 元 |
| 心跳资源 | 8,640 × 0.0625 = **540 GB·s/月** | 占 100 万 GB·s 的 0.05% | 0.060 元 |
| 日常互动 | 孩子一天说 50 次宠物相关 → 1,500 次/月 + 94 GB·s | — | 0.012 元 |
| 外网出流量 | 请求 2 KB / 响应 3 KB → 1 万次约 50 MB | 占 2 GB 的 2.5% | 0.040 元 |
| **合计** | 约 1 万次/月、约 1,000 GB·s/月 | **0 元** | **≈ 0.12 元/月** |

**结论：前三个月 0 元；之后约 0.1 元/月，一年一块多钱。**
说"永久免费"不严谨 —— 准确说法是"三个月后成本低到可以忽略，但确实不是 0"。

### 还有一项容易漏掉的：日志服务 CLS

SCF 的运行日志默认投递到 CLS，这是**另一个产品、另一本账**：

- CLS 新用户开通时自动送 10U × 3 个月的资源包（类似代金券），够用很久。
- 资源包用完后按量计费。我们每天的日志只有几百字节，**写流量/索引流量/存储都是分钱级**。
- 但 CLS 有 `分区数量 0.04 元/个/日` 这一项，一个日志主题一个分区就是 **约 1.2 元/月** ——
  这一项比 SCF 本身还贵。**不想付就在函数配置里把「日志投递」关掉**，代价是以后排查问题没有线上日志。

三个省钱的补充：
- 心跳只在设备处于**待命/聆听**时发，说话、升级、配网阶段不发。
- 连续失败 3 次后自动退避到 15 分钟一次，断网时不会按原频率硬撞。
- 想彻底关掉就把 `PET_HEARTBEAT_SEC` 设成 0，家长指令改成「孩子下次跟小智说话时送达」。

## 三个必须知道的实现细节

**1. 为什么自己拼 zip**
Windows 上用 PowerShell 压出来的路径是 `scf\index.js`（反斜杠），ZIP 规范要求 `/`。
Linux 解压时会把整串当一个文件名，云函数启动直接 `MODULE_NOT_FOUND`。`build.mjs` 自建
zip 结构并检查这一项。

**2. 为什么不用 `esp_http_client_perform`**
它在没有设置 `on_data` 回调时，会把响应体读进内部 buffer 就丢掉。之后再调
`esp_http_client_read` 只能拿到空字符串 —— 现象是「HTTP 200 但 body 为空」，
排查非常费劲。固件改成手动 `open → write → fetch_headers → read → close`，没有这个歧义。

**3. 为什么不用 `Settings` 类存状态**
它在写入失败时走 `ESP_ERROR_CHECK`，会**直接 panic**。NVS 分区只有 16KB，
状态约 1.4KB，多写几次就有撑满的可能。固件自己封装 NVS 读写，失败只打 warning，
内存态继续跑 —— 玩具不该因为存不下历史流水就重启。
